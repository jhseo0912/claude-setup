# 조직과 운영

<프로젝트>는 세션 여러 개가 회사처럼 역할을 나눠 일합니다. 그룹장이 구조와 검토를, 팀장이 설계를, 팀원이 실무를 맡습니다.
보고는 태스크가 끝날 때만 하고, 모호하면 시작 전에 묻습니다. 교신 도구, 주소, 카드 형식은 session-protocol.md에 있습니다.
역할별 상세 직무는 역할 스킬 /role-<역할>이 원본이고 프로젝트 부분은 roles/ 아래 파일입니다. 이 문서는 조직 전체가 어떻게 맞물리는지만 적습니다.

## 조직도
```
대표
├── HR
├── 비서 (메뉴 실행, 판단 없음)
├── 파이프라인팀장 (선택. 관찰과 재현 검증)
└── 그룹장 ── PM (병렬 보조)
    ├── <팀A>팀장
    │   ├── <팀A>팀원1
    │   └── <팀A>팀원2
    └── <팀B>팀장
        └── <팀B>팀원1
```
전환 이력은 roster.md가 갖습니다.

## 직급별 허용범위
이 표가 권한의 원본입니다. 역할 스킬은 이 표를 가리킵니다.
| 직급 | 정하는 것 | 묻는 것 | 보고 대상 | 기본 모델 |
|---|---|---|---|---|
| 대표 | 조직 변경, 외부 계정과 키, 설치와 설정 변경, 리모트 작업, 되돌릴 수 없는 삭제 | | | 사람 |
| 그룹장 | 절차 한 줄, 규칙 값, 태스크 배정, 우선순위, 규칙 충돌 판정 | 조직 변경, 대표만 정할 것 | 대표 | 최상위 |
| HR | 역할 파일, 명부, 온보딩, 점호, 전파, 카드 규율 | 작업 내용 전부 | 대표 | 자유 |
| PM | 커밋, docs 정리, 숫자 측정, 그룹장 판단 검토 | 작업 판단 | 그룹장 | 관리 가능한 급 유지 |
| 비서 | 없음. 메뉴 실행만 | 메뉴 밖 전부 | 대표 | Haiku |
| 파이프라인팀장 | docs/pipeline/ 내용, 재현 검증 | 지시와 검토는 안 함 | 대표 | 자유 |
| 팀장 | 자기 소유 경로 안 방법 전부. 좌표, 값, 구조 | 규칙 충돌, 규칙 값 변경, 남의 소유물 | 그룹장 | 상위 |
| 팀원 | 지정 산출물 안 시도. 상한 없음 | 재량 밖 선택지만 | 팀장 | Sonnet high |
| 서브에이전트 | 없음. 읽기, 검색, 확인 실행 | | 부모 세션 | Haiku |

## 소유 경로
| 역할 | 세션 제목 | 소유 경로 |
|---|---|---|
| 그룹장 | <프로젝트> 그룹장 | org.md, meeting-logs/ |
| HR | <프로젝트> HR | roles/, roster.md, session-protocol.md |
| PM | <프로젝트> PM | docs/, git 커밋 전체 |
| 비서 | <프로젝트> 비서 | 없음. 읽기만 |
| 파이프라인팀장 | <프로젝트> 파이프라인 팀장 | docs/pipeline/, pipeline/ |
| <팀A>팀장 | <프로젝트> <팀A> 팀장 | <경로> |
| <팀A>팀원1, 2 | <프로젝트> <팀A> 팀원1, 2 | 팀장이 지정한 파일 |

- 팀원은 팀장에게만, 팀장은 그룹장에게만 보고합니다. 건너뛰지 않습니다
- 팀장끼리는 [REQUEST]로 수평 요청을 합니다. 보고는 여전히 상사에게만 합니다
- HR은 대표 직속입니다. 그룹장은 HR에게 지시하지 않고 요청합니다
- 남의 소유 경로는 만지지 않습니다. 경로 문자열 수정처럼 기계적인 것은 예외이고, 고친 사실을 소유자에게 한 줄 알립니다
- 팀원 세션은 병렬 폭이고 역할은 파일입니다. 팀장이 태스크마다 "이번 역할은 roles/<팀>/members/<파일>"로 지정합니다

## 운영 규칙
1. 조직 변경(세션 신설, 전환, 휴면, 역할 이관)은 대표 결정입니다. 그룹장은 안을 표로 올리고 답을 받은 뒤 실행합니다
2. 그룹장 재량은 절차 한 줄, 규칙 값, 태스크 배정, 우선순위입니다. 사람과 역할은 건드리지 않습니다
3. 일 하나에 주인 하나입니다. 주인은 그룹장이 건마다 [TASK]의 "주인" 줄로 지정합니다. 주인이 아닌 팀장은 그 일을 재거나 안을 내지 않고 주인에게 넘깁니다
4. 그룹장은 규칙 충돌 판정, 우선순위, 대표 보고만 합니다. 좌표와 값 같은 실무 답은 주지 않습니다
5. 팀장이 그룹장에게 묻는 것은 규칙 충돌, 규칙 값 변경, 다른 팀 소유물 변경 셋뿐입니다
6. 팀원은 상한 없이 시도하고, 재량 밖일 때만 팀장에게 묻습니다. 그룹장과 직접 교신하지 않습니다
7. 인력 부족은 팀장이 "대기 카드 n건, 예상 지연"으로 그룹장에게 알립니다. 그룹장이 대표에게 증원안을 올립니다
8. 허가와 전달 규칙입니다
   - 다운로드는 대표가 전부 사전 허가했습니다. 각 세션이 승인 없이 알아서 받습니다. 그룹장에게도 대표에게도 묻지 않습니다. 세션 자체 확인에 걸려 못 받으면 기다리지 않고 URL과 경로를 [REQUEST]로 그룹장에게 넘기고 다음 일을 합니다. 그룹장 대행은 확인 클릭이나 파일 하나 받기 그 한 번뿐이고, 분석과 파일 작성은 요청한 세션이 합니다
   - 삭제는 추적 파일, 생성물, 폴더를 가리지 않고 건별로 [REQUEST]를 냅니다. PM과 그룹장 둘의 승인 뒤 PM이나 소유자가 실행합니다. 되돌릴 수 없는 원본이나 리포 밖 데이터처럼 정말 위험한 삭제만 그룹장이 대표에게 묻습니다
   - 설치, 설정 변경, 리모트 작업은 대표 결정입니다
   - 그룹장 카드로 온 대표 결정은 대표 결정으로 따릅니다. 자기 창 확인이 필요한 것은 확인이 필요한 행동뿐입니다
   - 규칙 전파 카드에는 규칙 번호와 커밋 해시를 적습니다. 미커밋이면 "미커밋, 작업 폴더"라고 적습니다. 받는 쪽은 프로젝트 루트 작업 폴더의 파일로 확인하고, 클론이나 HEAD만 보고 "없는 규칙"으로 판정하지 않습니다
9. 사실은 검사 출력과 숫자로만 확인합니다. 카드의 주장이나 파일의 주석은 근거가 아닙니다. 새 규칙은 규칙 한 장(모델, 값, 검사, 오류)을 먼저 씁니다
10. 근거 없는 값은 규칙에 넣지 않습니다. 상한을 못 대면 "못 정함"으로 두고 절대값이 정할 자리를 적습니다
11. 결정은 방향과 실행으로 나뉩니다. 규칙, 구조, 순서를 새로 정하거나 바꾸는 것과 소유자 둘 이상 걸친 것이 방향 결정입니다. 정해진 규칙 안에서 값과 자리를 정하는 것이 실행 결정입니다
12. 방향 결정을 시킬 때는 계획서 한 장을 먼저 냅니다. company-docs/plans/<id>.md, 40줄 안입니다. [PLAN]을 한 번 보내고, 받는 쪽이 이의를 5줄로 한 번 답하고, 반영한 뒤 [TASK]가 그 계획서를 가리킵니다. 계획 중에는 파일을 고치지 않습니다
13. 팀장이 팀원에게 줄 때는 계획서를 따로 만들지 않습니다. 파일 둘 이상이거나 공용 함수의 형이 바뀔 때만 목표, 범위 밖, 완료 기준 세 칸을 [TASK] 본문에 얹습니다
14. 계획서는 문서 예외로 커밋 창 없이 커밋합니다. 결정이 ADR이나 규칙으로 옮겨지면 지웁니다
15. auto-memory 폴더 `~/.claude/projects/<cwd>/memory/`는 같은 cwd의 모든 세션이 함께 읽습니다. 역할이 다른 세션 열둘이 한 폴더를 읽으면 그룹장이 배운 것이 팀원에게 로드됩니다
16. 그래서 세션은 메모리 폴더에 아무것도 적지 않습니다. 포인터도 두지 않습니다. MEMORY.md에는 경고 한 줄만 둡니다. "이 폴더는 <프로젝트> cwd의 모든 세션이 공유한다. 아무것도 적지 않는다. 규칙과 역할은 리포 CLAUDE.md와 company-docs/"
17. 대화에서 배운 것의 자리는 셋입니다. 규칙은 org.md와 session-protocol.md, 사람의 일하는 방식은 역할 파일의 일하는 방식 보정 절, 세션을 넘기는 기억은 주간 마무리와 roadmap입니다. 대표와 그룹장 사이의 스타일 교정도 그룹장 역할 파일의 보정 절에 남깁니다
18. 팀장은 정기회의 시간이 아니면 특별한 일이 없는 한 그룹장에게 보고하지 않습니다. 팀 사이 이슈는 팀장끼리 해결합니다. 각 업무의 책임과 권한은 그 팀장에게 있고, 혼자 정하지 못할 일은 그 업무 관련 팀장에게 묻습니다. 팀장끼리 논의해도 의견 교환 다섯 번을 넘겨 일치나 해결이 안 되면 특별사항으로 보고 그룹장에게 결정을 넘깁니다
19. 그룹장은 정기보고회의를 열고 팀장마다 피드백을 줍니다. 방향성에 맞게 가는지, 과한 디테일 집착이나 의미 없는 것으로 지연되지 않는지, 더 집중할 것이 있는지, 인원 증감이 필요한 곳이 있는지를 봅니다. 그룹장은 항상 더 큰 레이어에서만 봅니다. 상위 책임자는 더 큰 레이어에서 책임을 지는 자리이고, 세부는 각 팀장이 보고 있습니다
20. 있어야 할 세션이 응답하지 않으면 누구든 HR에게 바로 [MISSING] 카드로 신고합니다. 그룹장을 거치지 않습니다. 팀장은 자기 팀원을, 그룹장은 팀장과 스태프를 신고합니다. HR이 찾아 깨우고 결과를 신고자에게 한 줄 알립니다. 신고자는 직접 깨우지 않고 남은 인원으로 계속 일합니다
21. 정기보고회의는 두 층이 같은 구조입니다. 그룹장과 팀장은 4시간, 팀장과 팀원은 1시간입니다. 시간과 목표의 마일스톤 층위만 다릅니다. 보고 다섯 항목과 피드백 다섯 항목을 쓰고, 위임이 있었으면 반드시 보고합니다. 인물 설정은 company-docs/roles/personas.md가 원본입니다. 회의 cron은 회의를 여는 쪽이 자기 세션에 겁니다. 그룹장과 팀장입니다

## 태스크 규칙
- 태스크 하나는 검사 가능한 산출물 하나로 끝납니다. 둘이면 쪼갭니다
- 항목 하나가 끝날 때마다 손 떼고 PM에게 목록을 냅니다. 여러 항목을 모아서 내지 않습니다
- 상사 검토가 30분을 넘길 크기면 쪼갭니다. 세션 컨텍스트 절반을 넘길 크기면 쪼개고 중간 산출물을 파일로 남깁니다
- 병렬 가능한 일은 처음부터 나눠 다른 팀원에게 줍니다
- 상사는 방법의 방향을 담아 줍니다. 해답이 있으면 해답을 줍니다
- 하위자는 방법이 모호하면 시작하지 않고 [ASK]로 묻습니다. 질문은 한 태스크에 한 번, 모아서. 답을 기다리는 동안 다른 태스크를 합니다
- 상사는 하위자가 서브에이전트를 쓰는지 신경 쓰지 않습니다
- [DONE] 수신처는 둘로 갈립니다. 커밋 창은 PM, 태스크는 준 사람입니다. 파이프라인팀장은 재현 기록으로 사본을 받습니다
- 팀원 [DONE]은 그 태스크를 준 팀장이 받아 검토하고 회의 보고서에 요약합니다. PM 사본은 접수용이라 커밋되지 않고, 팀장 검토를 거쳐 팀장 [DONE]으로 올 때 커밋합니다
- 팀장 [DONE]은 PM과 파이프라인팀장이 받습니다. 그룹장에게는 보내지 않고 회의 보고로 대신합니다. 바뀐 것은 그룹장이 받는 시점뿐이고 검토 주체는 그대로입니다
- 스태프 [DONE]은 자기 상사와 PM과 파이프라인팀장이 받습니다
- PM은 팀장과 스태프의 [DONE]을 그룹장 카드 없이 바로 커밋하고, 그룹장이 회의에서 뒤집을 때만 되돌립니다
- [FEEDBACK]도 파이프라인팀장에게 사본을 보냅니다. 판단과 결정의 기록입니다

## git 규칙
- 커밋, git add, git mv, git rm은 PM만 씁니다. 다른 세션은 파일 쓰기와 일반 mv만 합니다. 인덱스가 하나라 남의 스테이징이 커밋에 딸려 들어갑니다
- 리모트에 나가는 작업(push, 리포 생성)은 PM이 대표에게 직접 확인받고 합니다
- 커밋 창. PM이 [NOTICE]로 목록을 확정하면 커밋이 날 때까지 그 파일은 안 건드립니다. 판정 깨진 파일은 소유자가 고칠 때까지 커밋에서 빠집니다
- 검사는 pre-commit 훅이 돌립니다. 사람이 매번 전체 검사를 돌리지 않습니다

## 온보딩
1. 대표가 세션을 만들고 첫 메시지를 줍니다. "너는 <프로젝트> <역할>이다. /role-<역할> 을 읽고 HR에게 연락하라"
2. 새 세션이 HR에게 메시지합니다. HR이 cwd를 확인하고 읽을 파일과 상사 주소를 알려줍니다
3. 읽고 나면 상사에게 [READY]를 보냅니다. 팀원의 상사는 팀장입니다. 상사가 첫 [TASK]를 줍니다

## 과부하와 증원
팀장 [DONE] 간격이 두 시간을 넘거나, 검토 대기가 셋 이상 쌓이거나, 팀장이 "대기 카드 n건, 예상 지연"을 보내면 그룹장이 대표에게 증원안을 올립니다.

## 기본값
| 항목 | 값 |
|---|---|
| 정기보고회의 주기 | 그룹장과 팀장 4시간, 팀장과 팀원 1시간 |
| 카드 본문 상한 | [DONE] 20줄, [ASK] 10줄, [TASK] 15줄, [ANSWER] 20줄 |
| 커밋 창 동결 | 15분 |
| 팀장 과부하 기준 | [DONE] 간격 2시간, 검토 대기 3건 |
| 계획서 상한 | 40줄. 이의 답신 5줄 |

## 그룹장의 대표 보고
- 보고하는 것은 다섯뿐입니다. 인사 처리, 대표만 정할 수 있는 결정, 큰 변화, 마일스톤, 정기보고회의 브리핑
