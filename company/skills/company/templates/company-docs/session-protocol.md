# ADR-001: 세션간 통신 규약

## 결정
세션간 통신은 `SendMessage(to: 세션이름)`을 기본으로 씁니다. 주소 조회는 `ListAgents`로 합니다.
카드에 적는 세션 주소는 짧은 id입니다. 표기는 `<태스크id | 세션명 | 짧은 id>`입니다.

## 맥락
<프로젝트>는 여러 Claude Code 세션으로 구성됩니다. 세션마다 별도 프로세스라 직접 상태를 공유할 수 없고, 메시지로만 소통합니다.

## 규칙
- 발신 경로가 둘입니다. `SendMessage(to: 이름 또는 "이름 [ref]")`는 이름 기반이고, `ListAgents`가 매 줄에 찍는 대괄호 값이 짧은 id입니다. 세션 관리 도구(`mcp__ccd_session_mgmt__send_message`)는 긴 sessionId를 받습니다. 예: `local_c667b756-caea-412c-b046-4d9517f74fb1`. 어느 도구로 온 메시지든, 그 메시지의 발신 주소 형식에 맞춰 답합니다.
- 세션마다 쓸 수 있는 도구가 다릅니다. `SendMessage`가 아예 없는 세션도 있습니다. 그런 세션에는 `mcp__ccd_session_mgmt__send_message`로 긴 id를 써서 보냅니다. roster의 긴 id 열이 그 값입니다.
- 이름은 사람이 보는 라벨일 뿐 안정 식별자가 아닙니다. 이름 중복이 흔하고(로그에 동일 이름 세션 수십 개 확인), 세션 쪽에서 제목을 바꾸면 바뀝니다.
- 짧은 id가 `ListAgents`에서 유일하지 않으면 `이름 [ref]`로 보냅니다.
- roster에는 이름, 짧은 id, 긴 id를 같이 적습니다. 발송 전 `ListAgents`로 id가 아직 있고 이름이 맞는지 재확인합니다. 이름만 보고 과거 기록을 신뢰하지 않습니다.
- 자기 자신에게는 보내지 않습니다. `ListAgents` 결과 맨 위 줄이 항상 "이 세션의 이름과 id"입니다.
- 오프라인 세션은 메시지가 즉시 전달되지 않습니다. 해당 세션이 다음에 재개될 때 받습니다. 즉답이 필요한 전파는 온라인 세션 위주로 먼저 보냅니다.
- 새 세션이 생기면 HR이 온보딩 메시지를 보냅니다. 내용은 팀 소속 확인, 이 문서 경로 안내, 이름 등록 요청입니다.
- 전체 전파는 HR이 `ListAgents`로 <프로젝트> 소속 세션을 추려 순회 발송합니다. 소속 판단 기준은 roster.md에 등록된 이름입니다.
- 짧은 id와 긴 id 둘 다 고정 주소가 아닙니다. 세션이 재시작되면 바뀔 수 있습니다. roster에 적힌 주소로 연락이 안 되면, HR이 이름으로 `ListAgents`를 다시 검색해 새 id를 찾아 roster를 갱신합니다. 연락 두절을 이유로 그냥 포기하지 않습니다.

## 카드 형식
모든 세션 간 메시지는 아래 카드 하나로 시작합니다. id는 `<태스크id | 보낸 세션명 | 짧은 id>`이고 짧은 id는 roster.md 값입니다.

```
[TASK] <id>  <제목>
목표: 한 줄
산출물: 경로
완료 기준: 검사 방법 한 줄
방법: 방향 또는 해답
주인: 이 일의 담당 역할. 여럿이 걸치는 일에만 씁니다
참고: 읽을 파일
```
```
[DONE] <id>
산출물: 경로
검사 결과: 완료 기준 대비
판단한 것: 상사가 뒤집을 수 있는 결정 목록
남은 문제: 없으면 "없음"
```
```
[ASK] <id>
막힌 지점: 한 줄
선택지: 번호와 추천
```
```
[FEEDBACK] <id>  상사가 [DONE]에 답합니다. 승인, 반려, 뒤집는 판단
[ANSWER] <id>   상사가 [ASK]에 답합니다
[REQUEST] <id>  팀장 사이 수평 요청. 형식은 [TASK]와 같고 받는 쪽이 수락 여부를 한 줄로 답합니다
[PROPOSAL] <id> 파이프라인팀장이 그룹장에게 내는 기계화 제안. 채택 여부는 그룹장이 한 줄로 답합니다
[NOTICE] <id>   결정이나 규칙 변경 전달. 답 불필요
[INFO] <id>     사실 전달. 파일 이동, 경로 변경. 답 불필요
[READY] <역할>  온보딩 완료. 읽은 파일 목록. 수신처는 roster의 상사
[PING-SELF] <역할>  compact 뒤 자기 신상 알림. HR에게. 역할, 세션명, 짧은 id, 긴 id, 진행 중 태스크 id, 명부와 다른 점
[PING] / [PONG] <현재 태스크 id 또는 "대기">
[회의] <id>     4시간마다 정기보고. 팀장은 10분 안에 세 줄(끝난 것, 진행 중, 막힌 것), PM은 숫자 넷을 붙인다. 절차 원본은 역할 스킬 /role-group-lead
```
- [DONE]은 상사, PM, 파이프라인팀장에게 동시에 보냅니다. [FEEDBACK]은 받는 사람과 파이프라인팀장에게
- 카드에서 문서나 파일의 변경을 언급할 때는 커밋됐는지 작업 폴더에만 있는지 함께 적습니다. 받는 쪽이 클론에서 일하면 미커밋 변경은 보이지 않습니다
- 카드 하나에 태스크 하나. 여러 건이면 카드를 나눕니다
- 컨텍스트가 compact되면 훅이 복구 절차를 주입합니다. 세션은 ListAgents와 roster로 자기 주소를 확인하고 HR에게 [PING-SELF]를 보낸 뒤 일을 잇습니다. HR은 명부를 갱신하고 주소가 바뀌었으면 그 세션의 상사에게 한 줄 알립니다
- 상대가 먼저 보낸 메시지와 엇갈렸으면 "엇갈림"이라고 첫 줄에 적고 무엇이 이미 처리됐는지 밝힙니다

### 보고 빈도
- 상사에게 보내는 카드는 [DONE], [ASK], [REQUEST]에 대한 수락 답, 이 셋뿐입니다. 그 외는 보내지 않습니다
- 보내지 않는 것. 착수 알림, 접수 확인, 발주 현황, 중간 진행, 엇갈림 정정. 엇갈림은 다음 [DONE] 첫 줄에 한 줄로만 적습니다
- [DONE] 하나에 판단과 남은 문제를 다 담습니다. 같은 태스크로 [DONE]을 두 번 보내지 않습니다
- PM은 커밋 완료를 보고하지 않습니다. 되돌리기, 충돌, 잘못 들어간 파일 같은 사고만 [INFO]로 알립니다
- HR은 온보딩 완료를 세션당 한 줄로만 알립니다. 확인 메시지는 보내지 않습니다
- 답이 필요 없는 [NOTICE], [INFO]에는 회신하지 않습니다. 상사도 마찬가지로, 답이 필요 없는 메시지에 "접수"를 보내지 않습니다
- 카드로 시작한 턴은 카드 처리와 파일 수정만 하고 채팅 출력 없이 끝냅니다. 세션 대화는 앱이 저장하므로 세션별 로그 파일을 따로 만들지 않습니다. 남길 지식은 docs, ADR, meeting-logs, findings로 갑니다. PM 세션은 예외로 커밋 해시와 검사 결과를 한 줄 남깁니다. 대표가 화면으로 보는 유일한 창입니다
- HR 전파는 팀장과 PM까지입니다. 팀원에게는 팀장이 다음 [TASK] 카드에 필요한 줄만 얹습니다. 팀원은 CLAUDE.md, 자기 역할 파일, 카드에 적힌 참고 파일만 읽습니다
- 카드 본문 상한. [DONE] 20줄, [ASK] 10줄, [TASK] 15줄. 숫자, 경로, 명령만 씁니다. 과정 서술과 자기 평가 문장은 안 씁니다. 넘치면 파일로 쓰고 경로만 싣습니다
- 상한 넘긴 카드는 받는 쪽이 반려하고 다시 냅니다

## 대가
- 이름 기반 주소라 세션 이름이 바뀌면 이 문서와 roster를 같이 갱신해야 합니다.
- id도 재시작마다 바뀔 수 있어 완전한 고정 키가 아닙니다. 결국 이름 재검색이 최후 수단이라 이름 표기를 정확히 관리하는 게 중요합니다.
- 도구가 둘이라 상대가 어느 도구로 보냈는지 매번 확인해야 합니다.

## 재검토 조건
세션 수가 늘어 이름 충돌이 잦아지거나, 팀 외부 세션과 혼동이 반복되면 고유 ID 기반 주소록으로 전환을 재검토합니다.
