# roles/

일반 직무는 역할 스킬에 있습니다. 그룹장 /role-group-lead, HR /role-hr, PM /role-pm, 비서 /role-secretary, 파이프라인팀장 /role-pipeline, 팀장 공통 /role-lead, 팀원 공통 /role-member.
이 폴더에는 프로젝트 고유 직무만 둡니다. 폴더는 조직도와 같은 모양입니다.
인물 설정은 personas.md가 원본입니다. 역할 파일은 직무를, personas.md는 그 직무를 맡은 사람의 경력과 시선을 적습니다.
- <팀>/lead.md  팀장. role-lead 위에 얹는 것만. 맡은 일, 소유 경로, 먼저 읽을 프로젝트 문서, 첫 태스크
- <팀>/members/<방법서>.md  팀원이 태스크마다 지정받는 방법. 할 일과 완료 기준
- common/<방법서>.md  여러 팀이 같이 쓰는 방법서. 하나만 둡니다
온보딩 순서는 CLAUDE.md, company-docs/org.md, 자기 역할 스킬, 이 아래 자기 파일입니다.

## 일하는 방식 보정 절
역할 파일마다 상사가 하위자의 습관을 한 줄로 남기는 절입니다. 규칙은 일의 값과 검사를 정하고, 보정은 사람의 습관을 담습니다. 섞지 않습니다.
- 형태는 "무엇을 이렇게 한다. 사례 날짜" 한 줄
- 하위자는 태스크 시작 때 읽고, 상사는 계획서를 쓰기 전에 읽어 예시 둘을 거기 맞춥니다
- 같은 되묻기나 같은 과함을 두 번 보면 만듭니다. 같은 뜻이면 합칩니다
- 규칙 값이나 도구로 올라가면 지웁니다. 두 달 동안 다시 안 나오면 지웁니다
- 절 상한 15줄. 하위자도 한 줄 제안할 수 있고 확정은 상사가 합니다

## 이 역할과 일하는 법 절
위 절의 거울입니다. 상급자 역할 파일에 두고 하위자가 상사의 주는 법과 읽는 법을 한 줄로 남깁니다. 확정은 상급자가 합니다.
- 수명과 상한은 일하는 방식 보정 절과 같습니다
- 헤딩은 두 절 다 정확히 이 문자열을 씁니다. "## 일하는 방식 보정", "## 이 역할과 일하는 법". 검사 도구가 이 문자열로 파싱합니다
- 이 두 절은 roles/ 소유 예외입니다. 쓰는 사람이 직접 고칩니다. 상사는 하위자 파일의 보정 절을, 하위자는 상사 파일의 일하는 법 절을, 그룹장은 대표 교정을 자기 파일에 씁니다. 카드로 중계하지 않습니다
- HR은 헤딩이 있는지와 15줄 상한만 봅니다. 내용은 보지 않습니다
