# commit — 커밋 메시지는 haiku가 쓴다

장황한 커밋의 원인은 세션 맥락이다. 작업한 모델은 과정을 다 알아서 다 적으려 한다.
그래서 메시지는 맥락 없는 haiku 서브에이전트가 diff만 보고 쓴다. 서사가 들어갈 통로가 없다.

## 형식

- 제목: `type(scope): 요약`. 명령형, 50자 이내, 마침표 없음
- 요약은 무엇을 구현·변경했는지 구체적으로. 대상과 수치를 담는다
  (나쁨: "연결 풀 크기 조정" / 좋음: "DB 커넥션 풀 100→20, 타임아웃 30s→5s")
- type: feat fix refactor perf test docs build chore 중 하나. scope는 생략 가능
- 언어: 리포의 최근 커밋 언어를 따른다. 없으면 한국어. type과 scope는 항상 영어
- 본문: 기본 생략. 변경이 여러 갈래라 제목 한 줄에 안 담길 때만 구현 항목 1~3줄
- 금지: 이유·배경·효과 설명, "이 커밋은/This commit" 서사, 파일 경로 나열
- 하니스가 붙이라는 푸터(Co-Authored-By 등)는 검사 대상이 아니다. 메시지 뒤에 그대로 붙인다

## 절차

1. 스테이징을 확정한다. `git status`와 `git diff --staged`. 비어 있으면 먼저 add
2. Agent 도구를 model "haiku"로 호출한다. 프롬프트는 아래 템플릿에 diff를 끼운다.
   diff가 2000줄을 넘으면 `git diff --staged --stat` 전체 + 핵심 파일 diff로 줄인다
3. 반환된 메시지를 위 형식으로 검사한다. 위반과 언어 불일치는 직접 고친다.
   haiku를 다시 부르지 않는다
4. 그 메시지로 커밋한다

## haiku 프롬프트 템플릿

```
git 커밋 메시지를 작성하라. 커밋 메시지 텍스트만 출력한다.
설명·인사·코드블록·도구 사용 금지.

규칙:
- 1행: "type(scope): 요약". type은 feat|fix|refactor|perf|test|docs|build|chore,
  scope는 생략 가능. 요약은 한국어 명령형, 50자 이내, 마침표 없음
- 요약은 무엇을 구현·변경했는지 구체적으로. 대상과 수치를 담는다
  (나쁨: "연결 풀 크기 조정" / 좋음: "DB 커넥션 풀 100→20, 타임아웃 30s→5s")
- 본문은 쓰지 않는다. 단, 변경이 여러 갈래라 한 줄에 안 담기면
  빈 줄 뒤에 구현 항목만 1~3줄
- 이유·배경·효과 설명 금지. "이 커밋은" 같은 서사 금지. 파일 경로 나열 금지

diff:
<git diff --staged 출력>
```
