# commit: 커밋 메시지는 haiku가 쓴다

장황한 커밋의 원인은 세션 맥락이다. 작업한 모델은 과정을 다 알아서 다 적으려 한다.
그래서 메시지는 맥락 없는 haiku 서브에이전트가 diff만 보고 쓴다. 서사가 들어갈 통로가 없다.

## 형식

```
type(scope): 요약

이 커밋은 <대상 기능과 한 일을 한 문장으로>.
- 상세 (xx 추가)
- 상세 (yy 제거)
```

- 제목: 명령형, 50자 이내, 마침표 없이 끝낸다. 무엇을 했는지를 대상과 수치로
  (모호: "연결 풀 크기 조정" / 구체: "DB 커넥션 풀 100→20, 타임아웃 30s→5s")
- type: feat fix refactor perf test docs build chore 중 선택. scope는 생략 가능
- 본문 첫 문장: "이 커밋은 ..."으로 시작하는 개요 한 문장
- 불릿: 구현 상세를 항목당 한 줄. 변경 갈래당 하나, 사소한 변경은 한 항목으로 묶는다
- 모든 문장은 diff에 있는 변경 사실을 서술한다. 이유나 배경이 필요하면 PR 설명이 그 자리다
- 언어: 리포의 최근 커밋 언어를 따른다. 없으면 한국어. type과 scope는 항상 영어
- 하니스가 붙이라는 푸터(Co-Authored-By 등)는 메시지 뒤에 그대로 붙인다

## 절차

1. 스테이징을 확정한다. `git status`와 `git diff --staged`. 비어 있으면 먼저 add
2. Agent 도구를 model "haiku"로 호출한다. 프롬프트는 아래 템플릿에 diff를 끼운다.
   diff가 2000줄을 넘으면 `git diff --staged --stat` 전체 + 핵심 파일 diff로 줄인다.
   Agent 도구가 없는 환경이면 `claude -p "<프롬프트>" --model haiku` 헤드리스 호출로 대신한다.
3. 반환된 메시지를 위 형식으로 검사한다. 위반과 언어 불일치는 직접 고친다.
   haiku 호출은 한 번으로 끝낸다
4. 그 메시지로 커밋한다

## haiku 프롬프트 템플릿

```
git 커밋 메시지를 작성하라. 아래 diff만 근거로 즉시 작성하고,
출력은 커밋 메시지 텍스트 하나뿐이다.

형식:
type(scope): 요약

이 커밋은 <대상 기능과 한 일을 한 문장으로>.
- 상세 (xx 추가)
- 상세 (yy 제거)

규칙:
- 1행: type은 feat|fix|refactor|perf|test|docs|build|chore 중 선택, scope는 생략 가능.
  요약은 한국어 명령형, 50자 이내, 마침표 없이 끝낸다. 무엇을 했는지를 대상과 수치로
  (예: "DB 커넥션 풀 100→20, 타임아웃 30s→5s")
- 본문 첫 문장은 "이 커밋은 ..."으로 시작하는 개요 한 문장
- 불릿은 구현 상세를 항목당 한 줄. 변경 갈래당 하나, 사소한 변경은 한 항목으로 묶는다
- 모든 문장은 diff에 보이는 변경 사실을 서술한다

diff:
<git diff --staged 출력>
```
