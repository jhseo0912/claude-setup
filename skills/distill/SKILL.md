# 증류 — md를 지식 압축으로

대상: 인자로 받은 파일/폴더. 인자 없으면 현재 리포의 CLAUDE.md·memory/·docs/를 훑어
위반(서사 로그, 상한 초과, 같은 사실 두 곳)을 찾아 목록 보고 후 진행한다.

## 원칙

- 리포에 이미 문서 규약이 있으면 그것을 따른다 — 새 구조를 덮어씌우지 않는다
  (예: "닫힌 길" 절이 결정 기록이면 ADR 폴더를 새로 만들지 말고 거기에 합류)
- git 없는 대상은 삭제 전 중단하고 사용자에게 확인한다
- 옮기기 전에 대상 문서에 같은 사실이 이미 있는지 grep — 있으면 옮기지 않는다 (원본 한 곳)

## 절차

1. **분류.** 문서의 각 정보 조각을 4갈래로 나눈다:

   | 형태 | 행선지 |
   |---|---|
   | 금지/제약 | constraints (또는 리포 규약의 해당 절) — 금지 + 이유 1줄 |
   | 결정 + 근거 | decisions/ ADR: 결정 1줄/맥락/이유(산문 허용)/대가/재검토 조건. 파일당 결정 1개, 40줄 상한 |
   | 지금 상태 | current_state.md 덮어쓰기, 15줄 상한 |
   | 사용법·설계 설명 | docs/ 해당 문서에 병합, 첫 3줄 요약 확인 |

2. **삭제.** 4갈래 어디에도 못 가는 것 — 과정 서사, 완료 확인 로그, 날짜별 진행 기록 —
   은 통째로 삭제한다. git 히스토리가 보존한다.
3. **검증.** 상한(라우팅 30/상태 15/ADR 40) 확인, 삭제한 파일을 참조하는 문서가 없는지 grep.
4. **보고.** 옮긴 것 n건(어디로), 삭제 n건, 판단이 애매해 사용자 결정이 필요한 것 목록.

## 합격 기준

6개월 뒤 처음 읽는 사람이 30초 안에 "이 정보가 나에게 필요한가"를 판단할 수 있으면 합격.
