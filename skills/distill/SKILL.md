# distill: md에서 남길 것만 추려내기

대상은 인자로 받은 파일이나 폴더다.
인자가 없으면 현재 리포의 CLAUDE.md, memory/, docs/를 훑어 문제를 찾는다.
찾는 것은 늘어진 기록, 분량 상한 초과, 같은 사실이 두 곳에 적힌 경우다.
목록을 보고한 뒤 진행한다.

지우는 작업이라 검증도 지운 쪽에 붙는다. 지운 모델은 왜 지웠는지 기억해서
자기 삭제를 감싸므로, 맥락 없는 haiku가 지워진 사실을 다시 분류해 판정한다.

## 원칙

- 리포에 이미 문서 규약이 있으면 그것을 따른다. 새 구조를 덮어씌우지 않는다.
  "닫힌 길" 같은 절이 이미 결정 기록이면 ADR 폴더를 새로 만들지 말고 거기에 합류한다
- git이 없는 대상은 지우기 전에 멈추고 사용자에게 확인한다
- 옮기기 전에 대상 문서에 같은 사실이 있는지 grep한다. 있으면 옮기지 않는다. 원본은 한 곳이다
- 판정 기준은 갈래 분류다. 언젠가 쓸모 있을지를 묻기 시작하면 아무것도 못 지운다

## 절차

1. **분류.** 문서의 각 정보 조각을 네 갈래로 나눈다.

   | 형태 | 행선지 | 형식 |
   |---|---|---|
   | 금지와 제약 | constraints, 또는 리포 규약의 해당 절 | 금지 + 이유 한 줄 |
   | 결정과 근거 | decisions/ ADR, 파일당 결정 하나, 40줄 상한 | 결정 한 줄, 맥락, 이유, 대가, 재검토 조건 |
   | 지금 상태 | current_state.md 덮어쓰기 | 15줄 상한 |
   | 사용법과 설계 설명 | docs/ 해당 문서에 병합 | 첫 3줄 요약 확인 |

2. **삭제.** 네 갈래 어디에도 못 가는 것은 통째로 지운다.
   과정 서술, 완료 확인 기록, 날짜별 진행 기록이 여기 해당한다.
   지우기 전에 수정 전 내용을 잡아 둔다. 커밋 전이면 git으로 꺼낼 수 있다.
3. **삭제 감사.** Agent 도구를 model "haiku"로 호출한다. 아래 템플릿에 원본과 정리 후 문서를 넣는다.
   누락으로 나온 것 중 제약과 결정은 해당 갈래 문서에 되살린다.
   상태는 지금도 유효한 사실이면 되살리고, 끝난 일의 완료 확인이면 그대로 둔다.
   haiku 호출은 한 번으로 끝낸다. 되살리는 것까지가 감사다.
   Agent 도구가 없는 환경이면 `claude -p "<프롬프트>" --model haiku` 헤드리스 호출로 대신한다.
4. **검증.** 분량 상한을 확인한다. 라우팅 30줄, 상태 15줄, ADR 40줄이다.
   지운 파일을 참조하는 문서가 없는지 grep한다.
5. **보고.** 옮긴 것 몇 건과 행선지, 지운 것 몇 건, 감사로 되살린 것 몇 건,
   판단이 애매해 사용자가 정해야 할 목록.

## haiku 프롬프트 템플릿

```
너는 문서 정리 결과를 감사한다. 도구 없이 아래 내용만 보고 즉시 답하라.

원본 문서를 갈래별 문서로 추려냈다. 원본에는 있는데 정리 후 문서 어디에도 없는
사실을 전부 찾아라. 찾은 사실 각각을 다음 중 하나로 분류하라.

- 제약: 금지나 한계
- 결정: 무엇을 왜 골랐는지
- 상태: 지금 어떠한지, 무엇이 남았는지
- 사용법: 어떻게 쓰는지
- 기록: 과정 서술, 날짜별 진행, 완료 확인

기록으로 분류된 것은 지워진 게 맞다. 나머지 넷으로 분류된 것만 "누락:" 아래
한 줄씩, 갈래 이름과 함께 나열하라. 누락이 없으면 "누락: 없음"이라고 적어라.

[원본]
<수정 전 문서>

[정리 후 문서들]
<갈래별 결과 문서>
```

## 합격 기준

감사 누락이 없거나 전부 복구되고, 분량 상한을 지키면 합격이다.
6개월 뒤 처음 읽는 사람이 30초 안에 "이 정보가 나에게 필요한가"를 판단할 수 있어야 한다.
